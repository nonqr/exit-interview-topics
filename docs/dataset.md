# Синтетический датасет экзит-интервью

## Зачем синтетика

Реальные экзит-интервью содержат персональные данные и недоступны студентам. Поэтому датасет
сгенерирован большой языковой моделью (LLM) по заранее заданной таксономии причин увольнения.
Каждый текст создавался под конкретную причину, поэтому для всех записей известна **эталонная метка**.
По ней мы оцениваем, насколько темы, найденные моделью, совпадают с реальными причинами (ARI, NMI).

## Как получен

1. **Таксономия** (`src/generation/taxonomy.py`): 10 причин увольнения с описанием и смещениями
   по отделам и стажу.
2. **Тексты** (`data/synthetic_source/<тема>.txt`): примерно 45–50 ответов на каждую причину и
   25 бессмысленных ответов («нет», «-», «всё ок»). Тексты сгенерированы LLM с требованиями:
   разная длина и стиль, разговорная речь, опечатки, разный пол автора, без повторов формулировок.
   Примерно 9% ответов содержат вторую причину, она помечена префиксом `[код]`.
3. **Сборка** (`src/generation/build_dataset.py`):
   - добавляет метаданные: отдел, должность, стаж, возраст, формат работы, оценку, дату;
   - согласует метаданные с текстом: ответ про склад попадает в «Логистику и склад», про пенсию — к
     сотруднику 58+ лет;
   - портит часть текстов, чтобы было что чистить: ВЕРХНИЙ РЕГИСТР, двойные пробелы, «!!!»,
     эмодзи, «е» вместо «ё»;
   - добавляет 6 точных дублей строк (имитация двойной отправки формы).

Генерация детерминирована (`SEED = 42`): повторный запуск даёт тот же файл.

## Файлы

| Файл | Что внутри |
|---|---|
| `data/raw/exit_interviews.csv` / `.xlsx` | То, что HR загружает в сервис. **Без меток.** |
| `data/raw/exit_interviews_labeled.csv` | То же самое плюс эталонные метки. Только для оценки качества. |

## Поля

| Поле | Описание |
|---|---|
| `id` | Идентификатор анкеты `EX-0001` |
| `reason_text` | **Свободный ответ: почему уходите.** Основное поле для анализа |
| `exit_date` | Дата увольнения, 2024-01-01 … 2025-12-31 |
| `department` | Отдел (8 вариантов) |
| `position` | Должность |
| `tenure_group`, `tenure_months` | Стаж в компании |
| `age` | Возраст |
| `work_format` | Офис / Гибрид / Удалённо |
| `satisfaction` | Общая оценка работы в компании, 1–5 |
| `would_recommend` | Порекомендовал бы компанию: Да / Нет |
| `true_topic`, `true_topic_name` | Эталонная основная причина (только в `_labeled`) |
| `secondary_topic`, `secondary_topic_name` | Вторая причина, если есть (только в `_labeled`) |

## Темы

| Код | Тема | Заложенная закономерность |
|---|---|---|
| `salary` | Низкая зарплата | чаще колл-центр, склад, производство |
| `management` | Конфликт с руководителем | чаще продажи; самая низкая оценка |
| `career` | Нет карьерного роста | стаж 1–5 лет; финансы, HR, маркетинг |
| `workload` | Переработки и выгорание | сильно чаще IT |
| `schedule` | График и формат работы | резкий рост с марта 2025 (отмена удалёнки) |
| `team` | Атмосфера в коллективе | новички до года |
| `personal` | Личные обстоятельства | самая высокая оценка компании |
| `processes` | Бюрократия и организация работы | стаж 5+ лет, финансы, IT |
| `conditions` | Условия труда и соцпакет | склад и производство |
| `content` | Неинтересные задачи | новички до полугода |
| `noise` | Нет содержательного ответа | должна отфильтровываться предобработкой |

Эти закономерности заложены специально: хороший дашборд должен помочь HR их обнаружить.

## Особенности, которые нужно учесть

- Ответы короткие: в среднем 9 слов. Для LDA это тяжёлый случай, у эмбеддингов здесь преимущество.
- Ответы `n/a` и `-` pandas по умолчанию читает как пустые значения (`NaN`). При загрузке используйте
  `keep_default_na=False` или явно обрабатывайте пропуски.
- Первый baseline (лемматизация, TF-IDF, NMF на 10 тем): ARI 0.11, NMI 0.20. LDA: ARI 0.03.
  Это точка отсчёта для улучшений.
