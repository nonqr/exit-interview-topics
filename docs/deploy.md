# Запуск для показа и публикация

Для защиты сервис запускается **в ноутбуке Kaggle** на бесплатной видеокарте и открывается по
публичной ссылке. Запасной вариант — запуск на своём ноутбуке без интернета. Постоянная публикация
(Hugging Face Spaces, свой сервер) понадобится, только если проект пойдёт дальше.

| | Kaggle (основной) | Свой ноутбук (запасной) | Hugging Face Spaces (потом) |
|---|---|---|---|
| Стоимость | бесплатно | бесплатно | PRO, $9/мес (Docker-Spaces с середины 2026 платные) |
| Видеокарта | T4, 15 ГБ | не нужна | нет (CPU) |
| Новый файл, точный режим | секунды | около минуты на 200 ответов | несколько минут |
| Ссылка | публичная, пока открыт ноутбук (до 12 ч) | только на этом компьютере | постоянная |

## Kaggle

### Один раз: подготовка

1. Аккаунт на https://www.kaggle.com с **подтверждённым телефоном** (Settings → Phone verification):
   без этого Kaggle не включает в ноутбуках интернет и видеокарту.
2. **Create → New Notebook**, затем **File → Import Notebook** и загрузите
   [`notebooks/demo_kaggle.ipynb`](../notebooks/demo_kaggle.ipynb) (файл или ссылку на него в GitHub).
3. В панели справа, раздел **Session options**:
   - **Accelerator → GPU T4 x2** (P100 не подойдёт: современный PyTorch её больше не поддерживает);
   - **Internet → On**.
4. **Save Version** не обязателен: достаточно, что ноутбук сохранён в вашем аккаунте.

### Каждый показ

1. Откройте ноутбук и нажмите **Run All**.
2. Подождите 5–8 минут: шаг 2 ставит зависимости, шаг 3 скачивает модели (~10 ГБ) и загружает их
   на видеокарту, шаг 4 выдаёт ссылку вида `https://….trycloudflare.com`.
3. Ссылка открывается с любого устройства. Её можно показать на проекторе и дать преподавателю.
4. **Не закрывайте вкладку** с ноутбуком: сессия работает, пока она открыта (не дольше 12 часов).
5. После показа — шаг 6 и кнопка ⏻ (остановить сессию): иначе тратится недельная квота видеокарты.

Запустите ноутбук за 15–20 минут до начала: первый запуск после перерыва может занять больше времени.

### Что внутри

- `src/app/serve.py` загружает модели **до** старта сервиса. Streamlit выполняет страницу в том же
  процессе, поэтому модель остаётся в памяти, и первый же загруженный файл считается сразу.
- Эмбеддинги демо-датасета посчитаны заранее и лежат в `data/embeddings/`: демо в точном режиме
  открывается за 2 секунды, даже без видеокарты.
- Модель сама выбирает видеокарту, если она есть. На T4 вместо bfloat16 используется float16
  (bfloat16 аппаратно поддерживают только видеокарты Ampere и новее).
- PyTorch, numpy и scipy берутся из образа Kaggle (они собраны под его видеокарту), остальные
  зависимости ставятся ровно тех версий, что в `requirements-app.txt`.
- Публичную ссылку даёт бесплатный туннель Cloudflare (Quick Tunnel, без регистрации). Ссылка
  меняется при каждом запуске. Если она перестала открываться, перезапустите шаг 4.

### Что проверено

- Шаги 1–3 ноутбука в окружении, похожем на Kaggle (Python 3.11, PyTorch 2.6, numpy и scipy
  не наших версий): зависимости ставятся, обе модели загружаются до старта, сервис отвечает,
  демо открывается за 2 секунды, новый файл считается без повторной загрузки модели.
- Не проверены здесь: видеокарта и туннель (нужен аккаунт Kaggle). Первый запуск на Kaggle
  сделайте заранее, за несколько дней до защиты.

### Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Шаг 1: «Видеокарта не включена» | Session options → Accelerator → GPU T4 x2, затем Run All |
| Шаг 2: ошибка `git clone` или `pip` | Session options → Internet → On (нужен подтверждённый телефон) |
| Шаг 3: «Сервис не запустился» | Лог выводится под ячейкой. Частая причина — выбрана P100 вместо T4 |
| Шаг 4: «Туннель не поднялся» | Запустить ячейку ещё раз |
| Ссылка открывается, но страница пустая | Подождать 10–20 секунд и обновить: ссылка становится доступна не сразу |

## Свой ноутбук (запасной вариант)

Если на защите нет интернета или Kaggle недоступен:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

```bash
pip install -r requirements-app.txt
```

```bash
python -m src.app.serve
```

Сервис откроется на http://localhost:8501. Демо в точном режиме работает сразу. При первом запуске
модели скачиваются (~10 ГБ), поэтому сделайте его заранее, дома. Чтобы не занимать память
моделью Qwen (~8 ГБ), можно загрузить только быструю:
`python -m src.app.serve --preload intfloat/multilingual-e5-large-instruct`. Тогда новые файлы
считайте в быстром режиме: около 20 секунд на 200 ответов.

## Hugging Face Spaces (если проект пойдёт дальше)

С середины 2026 года Hugging Face разрешает Docker-Spaces на бесплатном CPU только с подпиской PRO.
Всё для публикации уже подготовлено и проверено:

| Файл | Зачем |
|---|---|
| `Dockerfile` | Образ сервиса: PyTorch для CPU, зависимости, модели скачиваются при сборке |
| `src/app/warmup.py` | При сборке скачивает модели и прогоняет пробный анализ во всех режимах |
| `deploy/space_README.md` | Карточка Space: `sdk: docker`, порт 8501 |
| `deploy/deploy_space.py` | Собирает нужные файлы и загружает их на Space |
| `.github/workflows/deploy-space.yml` | Автоматическая публикация после каждого изменения в `main` |

После оформления PRO на аккаунте Hugging Face:

```bash
HF_TOKEN=hf_ваш_токен python deploy/deploy_space.py <логин>/exit-interview-topics
```

Для автопубликации из GitHub: **Settings → Secrets and variables → Actions**, секрет `HF_TOKEN` и
переменная `HF_SPACE` = `<логин>/exit-interview-topics`. Первая сборка занимает 15–30 минут.

Тот же Docker-образ подходит для сервера внутри компании — для реальных HR-данных публичный
сервис не годится:

```bash
docker build -t exit-interview-topics .
```

```bash
docker run -p 8501:8501 exit-interview-topics
```
